# Plan: simplify ordinary sub-agent calls

Gate: plan. Binding scope: [goal.md](goal.md). Design document: N/A. Current PR #50 and branch retained.

## Goal alignment and first principles

The runtime owns execution, the runner owns mechanical startup/result collection, and the caller owns task context and use of results. Project workflow requirements own audit decisions. Repeating machine checks in the caller and applying a provider test protocol to all tasks does not prove task correctness. A canary tests one read; an existing pathname in final answer can be consumed directly.

Decisions below only simplify the confirmed ordinary-call path. Only the user-approved additive statistics fields are needed; no new workflow protocol or abstraction is necessary. One integrated behavior slice avoids paying multiple gates for coupled CLI/skill/document changes. Code facts and success signals are in goal.md.

## Contract and implementation decisions

1. Direct codex-agent-run / claude-agent-run remain default, accepting explicit cwd and plain nonempty task. Existing private logs and auto Claude UUID/instance remain. Confirm prompt files are readable regular files and whitespace-only tasks fail before launch; otherwise keep runtime argv/routing/permissions/persistence unchanged (statistics fields below are additive). Help identifies canary/artifact as optional.
2. sub-agent-preflight is optional, still emits key=value setup + quoted runnable command and never dispatches a model. Required arguments remain runtime/provider/cwd and exactly one task source. Label becomes optional, generated as `task-${run_dir##*.}` from the fresh mktemp run_dir suffix; explicit labels are safe filename components (letters, digits, underscore, dot, hyphen; not . or ..). Each run_dir is unique; remove the historical label search that unnecessarily prevents deliberate reuse in a different run_dir.
3. Check only the selected runner's --list-providers membership, selected launcher and selected Codex model card/home. Remove full catalog baseline comparisons and unrelated-runtime dependency. The runner remains authoritative for accepted aliases; preflight need only support listed canonical IDs, as documented.
4. All three task sources accept natural language, including discussion of CANARY, model/report markers or existing filenames; remove heading and broad stale-token regex checks. Reject empty or ASCII-whitespace-only (space, tab, CR, LF, vertical tab, form feed) bodies for all three sources before appending anything, with setup_status=fail and empty command. Direct runner input forms use the same non-whitespace rule. Copy supplied file bytes unchanged into private run_dir, append only a short final-answer instruction (conclusion, result-impacting issues/unfinished items, artifact paths if any). Never request runtime/provider/model self-report.
5. Add preflight --canary switch. Default creates no canary files, emits empty canary_file/canary_expected and sends no canary args/instructions. Explicit --canary creates the fresh files, rejects the generated token already occurring in task text, appends current proof instruction, and passes the paired existing runner args. Does not scan unrelated task text for historical canary syntax; actual current proof mismatch is still enforced when opt-in. No new runner canary switch needed. With explicit canary, final-answer/artifact examples of unrelated standalone CANARY lines must be fenced or indented; otherwise they count as conflicting proofs. Document this optional constraint, without restoring broad task-body rejection.
6. --artifact remains optional. If supplied, preserve new-regular-file and output-alias checks, copy paths into prompt and pass existing collection args. Without it, do not infer/parse final-answer paths or demand separate reports; users read actual files according to task needs. Existing source modifications need no new artifact report.
7. Preserve --deny-list/--full-access handling. Preflight validates the exact generated command with agent-sandbox --check, then emits that same argv behind the envelope. Default no-canary command works; configured canary/artifact checks must remain within existing readable inputs/write roots. No changes to Seatbelt enforcement, trusted adapter record or lifecycle.
8. Rewrite sub-agents SKILL around ordinary invocation, complete independent-context handoff, managed waiting, final-answer consumption, expected task verification and ordinary tool failure tolerance. No manual eight-item checklist, runtime/model self-report, mandatory headings, universal canary, extra artifact or fixed YAML. Explicit project requirements take precedence. Keep stop/parallel-write/permission constraints and bounded actual-failure retry guidance. Do not require detailed per-event logs with --detail; it changes output, not task acceptance criteria.
9. Put existing substantial isolation/canary detail in one references/advanced.md linked only when that capability is selected. Preserve known-copy responsibility, macOS limit, immutable prompt/fixed policy, no resume, fail-closed startup, alias/hardlink and credential limitations, trusted first stderr adapter hash, no native MCP/hooks/plugins/browser channels in isolation. This is progressive disclosure of existing constraints, not removal of enforcement.
10. Collected reports add wall_clock_seconds, usage and runtime_metrics. Measure runner elapsed seconds with zsh SECONDS (floating precision) from process startup until collection invocation, including setup/runtime/final-message handling; excludes the result adapter serialization and caller-side preflight/wait overhead. Detail mode keeps original raw behavior. Pass measured seconds via internal adapter argument; absent/invalid time is unavailable (null), not a fabricated zero. Internal argument is optional `--wall-clock-seconds`; a finite nonnegative float is reported, otherwise null (including absent/invalid text), without affecting task validation. `usage` is the verbatim JSON object from the single terminal event or null for missing/non-object values; no counter normalization or numeric coercion. Never sum or select nonterminal/streaming usage. Failed terminals may expose their actual reported usage. Absent or multiple conflicting terminals return usage=null and runtime_metrics={}, alongside existing validation rejection. For Claude preserve reported duration_ms, duration_api_ms, total_cost_usd and modelUsage in runtime_metrics; Codex has only what its terminal actually supplies. `runtime_metrics` is an object with only terminal `duration_ms`/`duration_api_ms`/`total_cost_usd` values that are finite nonnegative JSON numbers (bool/string/negative invalid => omitted), and `modelUsage` only if an object, copied verbatim without interpreting nested counters. Missing data returns null/empty metrics, successful zero fields remain zero; preserve cache/reasoning counts and raw logs. No new model requests or price estimation.
11. README EN/ZH recommends the minimal direct call, explains optional preflight/label/--canary/--artifact, removes mandatory fixed report language and universal log adjudication. Result validation_status remains a mechanical signal; needs_review is not a mandatory audit gate or proof of business failure. Final answer is task evidence, not user authorization or guaranteed correctness.

## Slice S1: ordinary calls with opt-in checks

- Slice cost rationale: runner input/timing changes are small shared edits; adapter statistics add bounded terminal extraction, not a new runtime contract. Preflight and SKILL carry most deletions. Both groups share runners, tests and README ownership; they can be verified independently within one slice. Splitting would duplicate ownership and review gates without resolving a demonstrated state dependency or production risk. Retain one integrated caller-experience slice, with separate input and metrics fixtures.
- Objective/outcome: same useful task result with reduced setup/reporting burden across both runtimes, optional preflight and optional envelope.
- Prerequisite: accepted plan commit.
- Allowed source/docs: scripts/sub-agent-preflight, scripts/codex-agent-run, scripts/claude-agent-run, scripts/agent-run-result.py, skills/sub-agents/SKILL.md, skills/sub-agents/references/advanced.md, README.md, README.zh.md.
- Allowed tests: tests/test_sub_agent_preflight.py, tests/test_agent_run_results.py; existing sandbox/native tests may be run without changing enforcement to fit assertions.
- Allowed evidence: docs/gateflow/sub-agents-defaults and docs/reviews.
- Call path: caller -> optional preflight -> optional envelope -> runner -> original runtime -> existing result adapter -> final answer/logs. Direct caller skips preflight. Result adapter mechanically retains terminal usage and measured time. Setup fails before model launch; optional contract violations keep existing explicit failures; successful runs keep existing summaries and runtime exit codes.
- Invariants: no loss of stdout/stderr/final-message retention; no manufactured runtime success; same provider/session/permission argv; no expanded Seatbelt write grants; configured checks still enforced; actual process exit required before completion. No other module fixes or new APIs.
- Stop/completion: slice passes after dual independent deepreview and accepted fixes re-reviewed; no live sync.

- Native synthetic local endpoint + Seatbelt two-runtime tests if a concrete changed-path risk warrants it; no actual provider probe required beyond authorized independent review routes, no key reads or third-party credential changes.

Review prompts must not feed intended behavioral answers for this forward task. Use a temporary synthetic runtime stub with the real repository runner and synthetic configuration, as part of an independent code review; no extra API/provider requests. The generated invocation and collected result are observable evidence.
