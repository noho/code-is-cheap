## Exact request-local namespace map

1. Build the immutable restoration map from the **actual current HTTP request**, before native flattening, and discard it at that request's end. Recognize only exact `type="namespace"` wrappers named `multi_agent_v1` or `collaboration` in top-level `tools`. These are the two known native descriptor formats, not prefixes, hardcoded future groups, or a hardcoded list of function names. Include only the function children actually advertised; never invent a capability. Kimi currently advertises v1 and MiMoFlash v2. No map from previous requests, child registries, shared globals or thread state.
2. A selected native wrapper must have the evidenced shape: object with `type`, nonempty string `name`, optional string `description`, array `tools`; each child is a function with a valid nonempty name and descriptor fields preserved. Duplicate native callable declarations, malformed native children, nested/mixed native children or native wrapper metadata that cannot be preserved by the selected transform fail sanitized 400 **before upstream send**. Request flattening accepts only the evidenced wrapper metadata (`type/name/description/tools`); response-only mapping may preserve extra native wrapper metadata unchanged when name/children can still be read unambiguously. Child schema/strict/additional fields are opaque preserved values, not material to revalidate against a new invented schema. Do not silently drop unsupported selected-native structure.
3. For Kimi only, replace each selected native wrapper at its list position with its function children in original order. Keep every child leaf, including name, parameters, strict and extension fields, except its description: deterministically prepend `Namespace <name>: <wrapper description>\n\n` to the existing description (empty when absent). This preserves the wrapper's evidenced descriptive information without aliases. On MiMoFlash the entire request remains identical relative to the preceding existing stages: **no flattening**, including the `functions` custom Code Mode wrapper.
4. Every unrelated namespace, its metadata, children/order and unknown fields stays semantically byte-equivalent (deep value equality; no JSON lexical reformatting guarantee when another field changes). Preserve all unknown/non-target descriptors; no generic MCP compatibility work. With no selected namespace/map, return original body bytes and retain the existing response path. Flags off introduce no validation or header changes.
5. Only **mapped native bare names** require uniqueness. Reject if a mapped name is also declared by another native child or any other callable declaration that could emit that bare name without namespace: top-level function/custom, another namespace's function/custom, including a known `input` `additional_tools` descriptor list. Do not flatten or derive restoration entries from `additional_tools`; inspect its known declarations for collisions and otherwise preserve it. Duplicate unrelated MCP names, duplicate unrelated `functions.exec` declarations, or duplicates within opaque schemas do not block a request. Do not choose first or alias ambiguity.
6. Conservative future-shape rule: inspect known descriptor containers, never recursively mine arbitrary parameters/metadata for `name`. An unknown descriptor with an explicit declaration-level name equal to a mapped native name is a scoped possible ambiguity and fails sanitized 400; an unknown descriptor with a different/absent name passes unchanged. Recognized namespace `tools` arrays may be inspected for such declarations while preserving the whole group. An opaque future container is not rejected merely because hidden callables cannot be disproved. There is no evidence that a nameless unknown type collides; do not turn a scoped uniqueness defense into global future-type rejection. Newly evidenced hidden mapped-name collisions require controller adjudication, not speculative blanket validation.
7. Preserve `input` history (including namespaced calls/outputs), instructions, additional tools, context, metadata, reasoning, parallel settings and every other field outside the selected `tools` wrappers. Only existing independent transformations may still affect their established targets. Kimi actually used `tool_choice="auto"`; absent/auto/none/required stay exact. A structured choice that explicitly targets a flattened native function is unsupported in this first contract: sanitized 400 before upstream, never erase its namespace. Structured unrelated choices remain unchanged. Response-only MiMoFlash preserves every tool choice. No general tool-choice or history adapter is proposed.

This first contract selects top-level native descriptors; the new observer must prove their exact request location. The old `native_descriptors` field aggregates top-level tools and known input additional-tools lists, so that field alone is not location proof. Dynamic-only native advertisement, compaction or future descriptor locations are not claimed covered. If fresh continuation needs them, preserve the failure and request a bounded contract revision; do not add cross-request lookup. For supported request compression, use the helper's existing decode/re-encode boundary. An undecodable/unsupported request keeps its existing passthrough behavior with no native map; it cannot be counted as repaired native coverage.

## Response restoration and streaming contract

For successful Responses bodies with a nonempty map, use one leaf transformation everywhere: on `type="function_call"` whose exact `name` is mapped, add its advertised namespace only when the original namespace is absent or JSON null. An explicit matching namespace is unchanged. Any explicit different namespace, including empty string or `functions`, is a protocol error; never override it. Unknown names, default functions, custom tool calls and every non-target object remain untouched. Preserve arguments as the original string, name, call_id, id, status and all other leaves. Never parse or rewrite arguments, tool results or agent lifecycle.

Apply consistently to `response.output_item.added.item`, `response.output_item.done.item`, `response.completed.response.output[]`, and nonstream JSON `output[]`. Argument deltas/interleaved calls do not need name/ID association state. No inference retry, synthetic completed/failed event, synthetic successful result, callback or tool execution is added by the adapter.

Parse SSE event framing incrementally, with arbitrary network chunks, UTF-8 codepoints, CRLF and multiple `data:` lines per event. Use joined data lines for JSON parsing and preserve event ordering and other SSE fields. Non-target events/comments/deltas are forwarded with their exact raw bytes. For changed events only, preserve all parsed values except the allowed namespace leaf; JSON lexical layout may differ. Do not reserialize every event. Ordinary streaming must flush the first complete event before upstream completion and each subsequent complete event as available; never collect the full response. Bound the in-progress event at **8 MiB**, with an analogous 8 MiB limit for buffered nonstream JSON. No total-response buffer or cross-call argument accumulation is justified. Test a long stream whose total exceeds the event cap with individually valid events.

The minimal encoding contract is identity or absent response `Content-Encoding` for an active map. Reject `gzip`, `deflate`, stacked or other nonidentity response encodings with a sanitized **502 before sending downstream response headers/body**; do not claim they were decoded by `http.client`. Existing `http.client`/urllib transport removes HTTP transfer framing, not content compression. No new response compression engine or Accept-Encoding rewrite is needed. Actual identity encoding must be recorded in fresh evidence; parsable old SSE alone does not prove a saved encoding header. If the chosen upstream returns compression despite current requests, that attempt is blocked evidence requiring a bounded contract decision, not an automatic retry with changed headers. Empty-map/flags-off/guardian traffic keeps existing behavior, including its encoding passthrough.

Active-map output retains the existing hop-by-hop filtering and connection-close transport. Remove stale `Content-Length` before streaming; do not replay upstream Transfer-Encoding or introduce double chunk decoding. Nonstream JSON may calculate the final length or use connection-close. Forward non-2xx upstream errors by the existing path; do not try to restore error payloads. Unsupported success media types on an active map fail sanitized 502 before output. This is a Responses compatibility stage, not a general reverse proxy.

Malformed JSON in a response data event, truncated framing/UTF-8/content, oversize events, or conflicting namespace must promptly stop the active adapter. Before downstream headers, return sanitized 502; after output begins, close upstream/downstream and log only a fixed protocol-error class. Do not send HTTP 400 midstream or fabricate terminal success/failure events. Validate an entire affected event before forwarding any of it. A later conflict cannot retract an earlier forwarded call; tests must demonstrate the stream fails without forwarding the conflicting event, and reviews must not claim transactionality across the whole response. Preserve legitimate existing upstream failure/terminal events unchanged; missing required terminal completion remains native failure. Guardian's existing transport retry decisions stay unchanged; namespace parsing must not extend them.

Production diagnostics should contain only route identity, flags/stage, counts and fixed error classes. No prompts, arguments, response bodies, credentials, private URLs or user-session identifiers in new logs/errors. Detailed fresh-test evidence follows the scoped sanitized capture contract below.
