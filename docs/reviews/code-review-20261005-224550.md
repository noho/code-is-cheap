- **修复风险（低/中）**: 低；需同时覆盖无旧文件、旧 key 文件和旧环境变量三种初始化/迁移组合，避免破坏现有迁移。

### 3-未修复-低-权限校验未强制 mode 600

- **入口/函数**: `load_endpoints()` 的私有文件权限检查。
- **文件(行号)**: `scripts/agent-endpoint.py:124-142`; `README.md:110`; `README.zh.md:106`.
- **输入场景**: 私有 `endpoints.json` 的权限为 `0400` 或 `0700`。
- **实际分支**: `stat.S_ISREG` 通过，且 `info.st_mode & 0o077 == 0`，因此校验通过；`--check` 返回 0。
- **预期行为**: README、错误信息和任务 schema 均要求文件必须为 mode `600`。
- **实际行为**: `0400`、`0700` 和 `0600` 都被接受，未检查完整 owner mode。

- **建议改法和验证点**: 使用 `stat.S_IMODE(info.st_mode) != 0o600`（或明确文档化允许的 owner-only modes），并为 0400/0700/0600 增加表驱动测试。
- **修复风险（低）**: 低；若有意支持只读 0400，应先显式修改契约和文档。

### 4-未修复-低-普通流干净 EOF 时诊断 dump 条件失效

- **入口/函数**: `_swap()` 的返回值分类与 `Handler._handle()` 的失败诊断分支。
- **文件(行号)**: `codex-agent/bin/codex-auto-review-shim:120-131`; `codex-agent/bin/codex-auto-review-shim:405-410`; `codex-agent/bin/codex-auto-review-shim:460-472`.
- **输入场景**: 管理路由的普通请求成功改写模型，但上游以干净 EOF 结束且未出现 `response.completed`。
- **实际分支**: JSON 解析成功后 `_swap()` 返回 `("...", "json")`；普通流循环结束时 `note="ok"`、`done=False`；dump 条件只接受 `how == "bytes"`，因此 request/response 都不写入 `FAILED_DIR`。
- **预期行为**: 该分支应保存普通流的未完成 request/response 证据，便于诊断“complete-but-not-a-stream”失败。
- **实际行为**: 日志仍显示 `completed=False`，但隔离复现 `dump_called False`；原来的 bytes 快路径已被移除，成功改写统一变成 `json`，条件成为不可达路径。
- **直接证据**: `_swap()` 在 `120-131` 不再产生 `bytes`；`Handler._handle()` 在 `467-469` 仍以 `how == "bytes"` 作为普通流 dump 条件。隔离复现日志为 `rewrite=json`、`completed=False`，且 `_dump` 未调用。
- **影响**: 非截断型普通流失败缺少 request/response artifact，降低故障定位和回归证据完整性；不会直接改变上游请求结果。
- **建议改法和验证点**: 将条件改为识别实际成功改写类别（如 `how.split("+")[0] in {"bytes","json"}`）或直接以 `not done` 驱动普通流诊断；增加干净 EOF、无 terminal event 的测试并断言 `_dump` 被调用。
- **修复风险（低）**: 低；注意不要把 guardian 的既有重试/缓冲语义改成普通流重试。
- **严重程度（低）**: 低
