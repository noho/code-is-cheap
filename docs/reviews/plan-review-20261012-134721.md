Review boundary: readonly plan review. No implementation, live sync, service restart, provider request, merge, push, or delegation was performed. The new artifact is the only repository change made by this review.

## Conclusion

`fail`

The plan is directionally aligned with the confirmed goal and preserves the requested max-effort, Kimi, GLM Flash, and catalog-fidelity decisions. It is not ready for implementation approval because the synthetic transport harness can accidentally use a real endpoint, and the install path can leave card/catalog pairs inconsistent after a partial failure. A third finding leaves the required before-shim evidence without a concrete capture mechanism.

## Scope And Goal Alignment

The plan maps the requested work to G1-G5: tracked source snapshots and staged validation, exact eight-profile selection with max defaults and Qwen/Kimi/GLM decisions, actual Codex and MiMo Lite/Code Mode execution, unchanged outer isolation and approval boundaries, and tests/docs before the later manual PR workflow. The non-goals correctly exclude high-risk diagnosis, finance work, native GPT/business/local conversion, migration frameworks, live deployment, and merge.

The plan does not broaden the goal into a general catalog updater, routing product, security redesign, or provider-support claim. The following checks were treated as binding:

- The five Downloads files match `source-inventory.json` SHA-256 and byte counts. Each root has a nonempty unique `models` array.
- The selected slugs are present: `deepseek-flash`, `glm-5.3`, `k3`, the three selected MiMo 2.6 entries, and `qwen3.8-max`.
- The actual selected metadata supports the plan's key decisions: Qwen has `context_window=983616` and no `max_context_window`; MiMo 2.6 is `code_mode_only` with `use_responses_lite=true`; GLM and Kimi advertise `max`; MiMo and Qwen do not advertise `max` in these files. These lists must remain unchanged.
- `codex` is version `0.162.1`; the platform package contains a Code Mode host at a package-internal path and `srt` is `0.0.79`. These are prerequisites only, not evidence that the runtime or a provider succeeds.
- The controller's parser/request controls show native parsing and request shape, including preserved `reasoning.effort="max"` and MiMo Lite `additional_tools`. Their HTTP 400 stops prove request construction only, not host execution, approval success, or provider acceptance.

## Assumptions Tested

1. A complete official catalog can be copied and assembled with only the authorized GLM Flash identity derivation and native guardian transport adaptations.
2. Missing optional vendor fields, including Qwen's absent maximum and MiMo's absent effective-context field, are handled by native defaults without inventing metadata.
3. The existing launcher, shim, sandbox, approval, result collection, and outer boundary contracts can remain intact while adding the MiMo host handoff.
4. The staged runtime harness can exercise all eight profiles with synthetic endpoints and no real credentials or provider traffic.
5. Existing failure behavior is sufficient for deployment rollback and paired card/catalog consistency.

Assumptions 1-3 are supported by the source and plan text. Assumptions 4 and 5 are not sufficiently specified or protected.

## Findings

### 1-未修复-[高]-Synthetic transport harness lacks two-hop URL wiring

- **位置**: `plan.md` lines 183-201, especially 189 and 197-198; `codex-agent/bin/codex-auto-review-shim` lines 107-117 and 324-326; `codex-agent/shim-routes.json`; `config/endpoints.example.json`.
- **问题类型**: 架构边界 / 测试缺口 / 安全边界
- **当前写法**: The plan says to start a synthetic upstream and the branch shim, then “rewrite only the temporary provider registry base URLs to those test ports.” It also requires endpoint-controlled wire model and Bearer key assertions while preserving endpoint IDs and route prefixes.
- **反例/失败场景**: The provider registry URL is only the Codex-to-shim hop. The shim independently resolves `endpoint_id` through `agent-endpoint.py` and forwards to the `base_url` in the fixture or user-owned `endpoints.json`. If the harness changes only `model-providers.toml`, the shim can forward to the default or inherited provider URL and key. A test can therefore make an accidental real request or fail before proving the intended transport. The plan does not state how the second hop is redirected to the OS-assigned upstream listener.
- **为什么有问题**: This violates the explicit no-live-provider boundary and prevents the test from proving the required endpoint override behavior. The route file contains only `endpoint_id`, `to`, and `request_prefix`; it does not contain a test upstream URL. The shim reloads the endpoint connection on every request, so the missing URL layer is not a harmless naming detail.
- **直接证据**: `route_url` selects `endpoint_module().connection(route["endpoint_id"], "codex")["base_url"]` at `codex-agent/bin/codex-auto-review-shim:107-117`; `_handle` resolves that connection at `:324-326` before forwarding. `codex-agent/shim-routes.json:1-76` has no upstream test URL. `scripts/sync-codex-providers.py:54-116` writes only the managed provider registry.
- **影响**: A synthetic run can contact a real endpoint, use an unintended key/model, or silently test only the Codex-to-shim hop. Required user endpoint/key preservation and no-live-call guarantees cannot be accepted from the planned evidence.
- **建议改法和验证点**:
  - Explicitly wire both hops in the temporary fixture: managed `model_providers.*.base_url` and shim listeners to the fixture shim ports, and each fixture endpoint override `base_url` to its synthetic upstream port.
  - Keep synthetic IDs, prefixes, upstream slugs, and keys; assert every upstream request is to a loopback fixture listener and that no non-fixture host is contacted.
  - Assert the endpoint resolver receives no inherited credentials and the upstream receives the expected synthetic Bearer key only.
- **修复风险（低/中/高）**: 中
- **严重程度（高/低/中/严重）**: 高

### 2-未修复-[高]-Catalog and card installation has no paired rollback

- **位置**: `plan.md` lines 135-141 and 237-245; `scripts/sync-codex-agent.sh` lines 36-41 and 60-81.
- **问题类型**: 回滚安全 / 部分失败 / 契约缺失
- **当前写法**: The plan validates staged outputs before installation and correctly states that source/card/generation/native-parse failures leave installed cards and catalogs intact. It then assigns later filesystem or I/O partial-install behavior to a future work unit and says broad transactional deployment is outside this goal.
- **反例/失败场景**: The generator succeeds, the catalog loop installs a new `kimi.json` containing `k3`, and the process exits before the card loop installs `kimi.config.toml`. The old card still selects `kimi-k3`, which is absent from the new catalog. Codex can fall back to unknown-model metadata or run with the wrong context/tool semantics. The same split failure can affect any of the eight profiles, and the provider registry has already been updated before staging.
- **为什么有问题**: G1 requires repository inputs to deploy exact selected entries and G2 requires exact model/context behavior. Two independent install loops do not preserve the card/catalog pair under an ordinary disk, permission, interruption, or process failure. Deferring a general transaction is reasonable, but it does not remove the migration-specific mismatch risk created by changing Kimi's logical slug and Qwen's budget.
- **直接证据**: `scripts/sync-codex-agent.sh:66-81` installs all catalogs and then all cards as separate loops. The plan's data-flow guarantee at `plan.md:141` covers validation failures, while `plan.md:245` explicitly leaves later filesystem/I/O partial installs unresolved. The current generator's own fallback warning points to unknown-model metadata as the failure mode.
- **影响**: A failed sync can leave a usable-looking installation with an incorrect model card/catalog pairing, silently downgrade context, lose official tool metadata, or require manual recovery. This is user-visible and difficult to diagnose.
- **建议改法和验证点**:
  - Keep the change narrow: install each profile's card and catalog as one backed-up pair, or preflight all copies and restore every replaced pair on any later failure.
  - Validate the post-install pair before returning success; a mismatch must fail visibly and restore the prior pair.
  - Move the provider-registry update after validation or include it in the same narrow rollback boundary.
  - Add injected failures after the first catalog, after the first card, and during a later pair install; assert old sentinents are restored and repeat sync is idempotent.
- **修复风险（低/中/高）**: 中
- **严重程度（高/低/中/严重）**: 高

### 3-未修复-[中]-Required pre-shim request evidence has no capture point

- **位置**: `plan.md` lines 195-200, 209-215; `codex-agent/bin/codex-auto-review-shim` lines 314-371 and 423-493.
- **问题类型**: 测试缺口 / 验收不可执行
- **当前写法**: The staged smoke requires selected logical slug and source instructions at the pre-shim request, and requires max effort before and after the shim. The plan permits shim code changes only for a demonstrated Lite forwarding defect.
- **反例/失败场景**: The synthetic upstream sees only the transformed request. The shim's normal log reports model and top-level tool names, while successful request bodies are not persisted. `json_fmt_fix`, ID rewriting, model replacement, and compression can occur before forwarding. A test can therefore prove the post-shim payload while missing a pre-shim instruction, effort, `additional_tools`, or Lite-header regression. Existing request controls do not execute the shim and cannot fill this gap.
- **为什么有问题**: The acceptance signal names two observation points, but the plan provides no test-only ingress hook or equivalent capture method. Unit mocks can inspect a request object after transformation, not prove what the real Codex process sent to the shim.
- **直接证据**: `_handle` reads and transforms the body at `codex-agent/bin/codex-auto-review-shim:314-371`; it logs only `_summary` at `:426-430`. Bodies are dumped only for non-2xx or selected stream failures at `:423-425` and `:488-493`.
- **影响**: Review can accept a shim or catalog change on incomplete evidence. Max effort, official instructions, Lite item shape, or tool transport could regress before the shim while all planned assertions still pass.
- **建议改法和验证点**:
  - Add a test-only shim ingress wrapper or narrowly gated capture that records the decoded pre-transform request and the upstream request separately.
  - Assert logical model, instruction rendering, reasoning effort, Lite header, `additional_tools`, and allowed transformations at both sides using synthetic data only.
  - Keep production logging unchanged and do not infer pre-shim state from the post-shim body or from HTTP-400 request controls.
- **修复风险（低/中/高）**: 低
- **严重程度（高/低/中/严重）**: 中

### 4-未修复-[低]-MiMo JSON-format adaptation is route-wide but described as guardian-only

- **位置**: `plan.md` lines 99-112 and 209-215; `codex-agent/bin/codex-auto-review-shim` lines 356-359; `codex-agent/shim-routes.json` lines 32-65.
- **问题类型**: 架构边界 / 过度耦合 / 残余行为
- **当前写法**: The plan calls `json_fmt_fix` a structured guardian-output adaptation and says to keep it for MiMo. The current route flag is enabled for all MiMo routes and the handler applies the downgrade to every request, not only a request whose model is `codex-auto-review`.
- **反例/失败场景**: A MiMo session request with `text.format=json_schema` is rewritten to `json_object` before the provider sees it. The planned smoke returns ordinary text and therefore does not detect a session structured-output regression. This is separate from the authorized Lite transport proof.
- **为什么有问题**: The plan claims guardian-only transport adaptation while preserving official session semantics, but the implementation boundary is route-wide. The behavior may be intentional provider compatibility, yet it is not named as a preserved limitation or covered by a session-level assertion.
- **直接证据**: `shim-routes.json` sets `json_fmt_fix=true` for all three MiMo routes. `Handler._handle` applies `json_object_format` at lines 356-359 without checking `guardian`.
- **影响**: Official structured-output behavior can change invisibly, and a future implementer may narrow or broaden the transform without an agreed contract.
- **建议改法和验证点**: Either explicitly document and test the route-wide downgrade as existing MiMo behavior, or scope the transform to guardian requests and add one session structured-output assertion. Do not silently describe the current behavior as guardian-only.
- **修复风险（低/中/高）**: 低
- **严重程度（高/低/中/严重）**: 低
- **状态**: `defer-candidate`

## Open Questions

- What exact test fixture object represents the synthetic upstream endpoint URL, and where is it written so the shim cannot resolve a default or user endpoint? This must be answered before implementation of `tests/test_official_catalog_runtime.py`.
- Does the installed `0.162.1` rollout token-count event expose `payload.info.model_context_window` as the usable context value (`934435` for Qwen) in the persisted fixture? The source-level behavior is consistent with that value, but the plan should pin the installed event shape rather than rely on a hand calculation.
- Is `json_fmt_fix` intentionally required for all MiMo session traffic, or only for guardian verdicts? The current plan wording and code disagree.
- The Code Mode host is present inside the platform package but is not exposed as a PATH command. The runtime test must prove the installed binary's actual host resolution and execution under `srt`; absence from PATH is not itself a failure.
