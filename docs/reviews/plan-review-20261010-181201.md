## Focused Contract Assessment

- **Cascade**: an added ancestor is scanned through the existing pending/visited graph; nested dangling links use the same strict -> ENOENT -> ALLOW_MISSING flow, keep exact target/ancestor deny entries, and emit one source-bearing report per discovery. Root, scan, unsupported-type, and conflict failures remain closed.
- **Multi-link conflict**: the focused case uses two independent missing targets/ancestors and a required input under one ancestor. It requires both expansion reports plus the existing concrete `required setup input is denied` path, proving localization without requiring a full role-origin system.
- **Verification**: first pass proves every existing deny by effective query and actual `PermissionError`; second pass accepts registered missing ENOENT only after its exact ancestor is in `verified_existing`. Target query=1 or ENOENT alone is never sufficient.
- **Scope**: the plan keeps the existing no-snapshot/external-mutation boundary. Its fixture materialization test is explicitly a local policy regression, not a new production concurrency guarantee.
