## Open Questions

- all-or-nothing 中止是否为预期终态？未知 content 形状的会话在 OpenAI 侧大概率同样无法 resume（残余 content 仍会被拒），故中止本身合理，但此类会话将无任何 documented 恢复路径；是否需要显式 `--skip-unknown`（大声报告、默认关闭）或文档化的手工处理流程？
- 崩溃截断尾行（append-only 日志常见）是否应容忍？当前工具对最可能受损的会话完全无解；Codex 自身 resume 时对尾部坏行的容忍行为本仓库内无法验证。
- `content: null` 修复目标的正确性依赖上游 issue #36551 与 Codex 原生格式（测试 fixture 以 `content: None` 表示健康 reasoning 项）；本仓库内无法独立验证 `null` 与删 key / `[]` 在 replay 上的差异。
- 是否存在 Codex 版本会在 reasoning `content` 中写入非 `reasoning_text` 类型的 part？若是，finding 3 的中止路径会命中 README 声称可修复的会话。
- `os.replace` 后不做目录 fsync：掉电最坏情况是修复未生效（备份已 fsync、原文件完好），无损坏风险——是否接受？
