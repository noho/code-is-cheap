## 设计挑战结论（任务指定重点）

1. **共享注册表必要性**：实机证据（裁决记录）显示 resume bootstrap 会解析会话记录的 provider，缺失即硬失败 `Model provider kimi not found`。旧设计（provider 嵌在每张卡内）下跨 profile resume 必然失败；注册表入 base 后任意卡组合均可解析。设计成立。
2. **变体 ID 拆分（`glm_flash`/`mimo_fast`/`mimo_flash`）**：集中化后单一 ID 无法同时服务两个端口，拆分是必要条件；注册表 9 条目的 base_url/env_key 与旧卡删除段逐一比对零漂移，与 `shim-routes.json`、`agent-tools.zsh` 映射经测试交叉锁定。
3. **升级窗口中间态**：新 sync 先写注册表再整文件换卡；窗口内"新 base + 旧卡"因卡段压过 base 段而保持旧路由，无 broken 窗口。sync 失败中止后续卡片部署是有意的正确耦合（新卡引用的变体 ID 必须先存在于 base）。
4. **普通 codex resume 模型保留语义（未提交 README 修订）**：`codex resume --help`（codex-cli 0.156.1）证实 `-p, --profile <CONFIG_PROFILE_V2>`（"Layer $CODEX_HOME/<name>.config.toml"）是 resume 的合法 flag，README 推荐的 `codex resume -p gpt-6-sol <session-id>` 与 launcher 实际展开一致；`codex exec` 同样支持 `-p`（:51），与 launcher `exec -p <id> resume` 接线一致。"plain resume 可恢复会话上次选中模型而非 base 默认"的表述与实机观测（bootstrap 绑定 recorded provider；`-p` 下选中模型被覆盖为 GPT-6-Sol）一致，hedge 用词（can/可能）与"续跑后真实请求路由未实测"的证据等级匹配——准确且不过度承诺。EN/ZH 修订语义对称。
