## Open Questions

- `--artifact` 是否正式允许目录？当前 `/tmp` 这类已存在目录会被记为 `exists=true` 并通过机械 artifact 检查，而 README 示例使用 `report.md`。若目录是合法 artifact，应明确其完成判据；否则应要求 regular file，并拒绝 pre-existing/stale 目标。
- 当前 Codex JSONL 是否还包含 collector 未识别的工具型 `item.type`（例如 web/search 或后续新增工具）？`Collection.codex()` 对未知 item type 静默不计数；在没有权威 schema fixture 的情况下，本轮不把它单独判为确定 defect，但保留为 protocol-version 风险。

## Residual Risk

- `agent-run-result.py` 的测试主要使用合成事件，未覆盖真实 provider 的完整 schema、超大多行 payload、并发日志替换和异常编码边界。
- Seatbelt kernel 测试未执行，因此 sandbox 参数问题由同路径静态证据和现有 parse/write-boundary 测试支持，未做真实内核写入反例。
- artifact 只检查存在性和文本中的 CANARY，不检查新旧、内容结构或写入者；`result_status=not_assessed` 和 controller 独立验收仍是必要边界，不能因 `validation_status=passed` 取消。
- 单条诊断原文虽在 runtime 日志中，但 runner 后处理异常的留存缺口见 Finding 2；修复前不能把报告中的 `logs.stderr` 视为所有 runner 层异常的完整单一日志。
