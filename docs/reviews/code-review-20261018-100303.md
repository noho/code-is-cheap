## Findings

### 1-未修复-中-带孤立 surrogate 的重复 JSON key 仍会把原生 0 变成外层 1 并丢失报告，或输出非法 UTF-8 JSON
- **入口/函数**: `scripts/agent-run-result.py` 的 `strict_object` → `Collection.note` → `read_events` 异常分支 → `main()` 的 `print(json.dumps(..., ensure_ascii=False))`；真实入口为 `codex-agent-run` / `claude-agent-run` 的 collected 模式。
- **文件(行号)**: `scripts/agent-run-result.py:11-17`（`strict_object` 把原始 key 拼进 `ValueError`）、`110-111`（`note` 仅做 `str()`）、`286-287`（捕获该异常并存为诊断）、`436-438`（不转义地 `print` 整个报告）。
- **输入场景**: 原生 CLI 的 JSONL 中出现一条畸形但可被 `json.loads` 解码的事件，重复 key 本身含孤立 surrogate，例如 `{"type":"error","\ud800":1,"\ud800":2}`；同一日志前后已有合法 final 和 terminal，原生退出为 0（或 7）。低 surrogate 变体 `\udcff` 触发同一路径。
- **实际分支**: `json.loads` 调用 `strict_object`；重复 key 抛出 `ValueError("duplicate JSON key: <surrogate>")`；`read_events` 捕获并把含孤立 surrogate 的异常文本存入 `diagnostics`；`collect()` 正常返回；`main()` 用 `ensure_ascii=False` 序列化后 `print`。
- **预期行为**: 按 `goal.md:8`、`scope-amendment.md:8,14` 与 `plan-v2.md` 行为矩阵，畸形帧应只产生带来源的 invalid-event 观察；collector 成功序列化观察时退出 0；可归属 final 与原生退出保持不变，外层退出精确等于原生退出。
- **实际行为**: 高 surrogate（`\ud800`）时 `print` 抛 `UnicodeEncodeError`，stdout 为 0 字节，collector 退出 1；`codex-agent-run` 打印 `primary result delivery failed ... known native exit=0` 并把外层退出改为 1。低 surrogate（`\udcff`）时 Python stdout 的 `surrogateescape` 把原字节 0xff 写入 JSON 文本，collector 退出 0，但调用方无法按 UTF-8 解析报告。二者都在真实 runner 路径可达。
- **直接证据**: 直接 collector 探针：`printf '%s\n' '{"type":"error","\ud800":1,"\ud800":2}' > out.jsonl` 后运行 `python3 scripts/agent-run-result.py --runtime codex --provider mimo --output out.jsonl --stderr err.log --exit-code 0`，实际 `collector_exit=1`，stderr 为 `UnicodeEncodeError: 'utf-8' codec can't encode character '\ud800' ...`，stdout 0 字节。完整 runner 探针（hermetic fake codex/tools，合法 final + 该畸形行 + native 0）实际 `outer_exit=1`、stdout 0 字节，stderr 同时含 collector traceback 与 `known native exit=0`。把该行换成 `\udcff` 后 collector 退出 0，但 stdout 含裸 0xff，`json.loads(raw.decode("utf-8"))` 抛 `UnicodeDecodeError`。现有回归只用孤立 surrogate 作为事件 **value**（`tests/test_agent_run_results.py:217`），`validate_event_text` 会在 dispatch 前拒绝并生成安全消息；重复 key 的异常文本绕过了这层校验，未被覆盖。
- **影响**: 原生 0 被改写为外层 1（或报告不可解析），可归属 final/terminal 无法交付给调用方；把本应是数据观察的问题升级为“primary result delivery failure”，直接违反薄封装契约的畸形输入保证。触发输入窄（需畸形重复 key 含 surrogate），但失败是用户可见的退出码错误/报告丢失。
- **建议改法和验证点**: 在报告序列化边界保证 surrogate-safe：例如 `json.dumps(..., ensure_ascii=True)`，或把 `json.dumps(..., ensure_ascii=False)` 的结果以 `utf-8` + `backslashreplace` 写入 stdout（后者保留普通 Unicode 字面量且把孤立 surrogate 写成合法 `\udXXX` JSON 转义；两者在解析后都保留原值）。可同时在 `note()` 对来自异常/路径的文本做 `backslashreplace` 清洗，作为纵深防御。新增公共 runner 回归：合法 final + `\ud800`/`\udcff` 重复 key 行，原生 0 和 7，断言外层码精确、stdout 可解析、`final_answer` 原文一致、诊断存在；不要按 warning 文本分类。
- **修复风险**: 低（仅序列化/诊断文本编码；schema 字段与值语义不变）。
- **严重程度**: 中。
