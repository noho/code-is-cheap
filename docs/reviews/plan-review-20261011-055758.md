## Findings

### 1-未修复-中-Proposed PEM validation is stricter than native Codex input handling
- **位置**: `plan.md:117-121,176`; validation case 5; documentation decision `plan.md:243-245`.
- **问题类型**: 契约缺失 / 测试缺口 / 非最优方案
- **当前写法**: The plan extracts only `-----BEGIN CERTIFICATE-----` through `-----END CERTIFICATE-----` blocks, requires at least one such block, and uses `ssl.SSLContext.load_verify_locations` on each block. The planned tests cover ordinary one-/multi-certificate PEM and malformed ordinary blocks, but not native-supported PEM labels.
- **反例/失败场景**: A caller supplies an explicit PEM bundle containing OpenSSL `TRUSTED CERTIFICATE` blocks (or a bundle whose valid certificate entries use that label). Installed Codex 0.162.1 explicitly normalizes those labels and ignores X509 CRL entries. The proposed regex finds zero ordinary blocks and rejects the file before launch as `invalid Codex CA bundle`, even though the native consumer can load it.
- **为什么有问题**: The confirmed goal says custom CA inputs are honored and asks for invalid-input handling. A validator narrower than the actual native consumer turns a valid custom input into a setup failure and can falsely blame the caller's certificate. The planned tests encode the narrower contract instead of exposing it.
- **直接证据**: Native binary strings at the Codex executable identify `normalizing OpenSSL TRUSTED CERTIFICATE labels in custom CA bundle`, `ignoring X509 CRL entries found in custom CA bundle`, and `no certificates found in PEM file`. The direct stdlib check accepted a normal `CERTIFICATE` block but rejected the identical DER relabeled `TRUSTED CERTIFICATE` with `SSLError: no start line`.
- **影响**: Some explicit enterprise/custom PEM bundles fail with a located but incorrect invalid-bundle error; the affected HTTPS startup remains broken for those users. The implementation would also need immediate rework or an undocumented input restriction.
- **建议改法和验证点**: Match the native accepted PEM forms: parse ordinary `CERTIFICATE` and `TRUSTED CERTIFICATE` entries using equivalent label normalization, ignore CRL entries as native does, and validate every certificate payload. Add tests for ordinary, trusted-label, mixed, CRL-containing, and malformed companion blocks. If maintainers intentionally reject trusted-label input, make that an explicit documented contract and test the distinct rejection instead of calling it generic invalid input.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
