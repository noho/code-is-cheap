## Findings

### 1-未修复-中-配置的 canary 输入在模型启动后才被校验

- **入口/函数**: `codex-agent-run` / `claude-agent-run` default collection, then `agent-run-result.py:Collection.collect`.
- **文件(行号)**: `scripts/codex-agent-run:405-417`, `scripts/codex-agent-run:492-495`, `scripts/claude-agent-run:378-390`, `scripts/claude-agent-run:434-447`, `scripts/agent-run-result.py:270-277`.
- **输入场景**: A caller selects the documented optional canary contract but supplies a missing/unreadable `--canary-file`, a missing/unreadable `--canary-expected`, or an expected file with an empty/whitespace-containing token.
- **实际分支**: The runners only check that the two canary options are paired (`codex-agent-run:408`, `claude-agent-run:382`), then create/open the runtime streams and invoke the model. The adapter reads and validates `canary_expected` only after runtime exit (`agent-run-result.py:270-277`), so the call is already a completed/expensive run before the configured check rejects it.
- **预期行为**: A configured canary setup should fail before model launch, as other explicit setup checks do, while post-run proof comparison should remain responsible for mismatch/missing proof.
- **实际行为**: Invalid canary inputs produce a post-run `validation_status=rejected` report (or a missing-proof rejection), rather than a pre-launch setup failure. The model/runtime has already run and consumed resources; the failure can also be mistaken for an Agent failure instead of an input/configuration failure.
- **直接证据**: The paired-ness check is the only canary validation before `run_codex`/the Claude runner call; the token/file read is in `Collection.collect` after the output event stream has already been produced. `scripts/agent-sandbox:162-169` prechecks pairing/readability/nonemptiness, and `sub-agent-preflight:172-177` creates the pair, but the default direct runner path does not.
- **影响**: Unnecessary model/runtime execution for an invalid opt-in check; delayed, less actionable failure attribution. It does not manufacture success because the adapter eventually rejects.
- **建议改法和验证点**:
  - Validate both canary paths before opening the runtime: readable regular files, expected token nonempty and whitespace-free, and preserve the existing paired-argument rule.
  - Keep the adapter's post-run proof/read checks unchanged.
  - Add tests for each missing/unreadable/empty/whitespace canary input on both runners and assert the synthetic runtime was never invoked.
- **修复风险（低/中/高）**: 低。The change is local setup validation and does not alter provider/session/permission argv.
- **严重程度（低/中/高/严重）**: 中。

### 2-未修复-中-显式 artifact 检查接受 hard-link/log alias

- **入口/函数**: Runner `--artifact` setup and `agent-run-result.py:Collection.collect` artifact postcondition.
- **文件(行号)**: `scripts/codex-agent-run:419-430`, `scripts/claude-agent-run:393-404`, `scripts/agent-run-result.py:323-339`, `skills/sub-agents/references/advanced.md:30-33`, `README.md:366-370`.
- **输入场景**: The caller requests a new artifact and a distinct output log. The artifact path is absent before dispatch, but the child creates it after the run as a hard link to the output log or another existing file.
- **实际分支**: Runner preflight rejects only an already-existing path, symlink, directory, or literal output alias. After execution, the adapter checks `exists`, `is_file`, and `not is_symlink`; a hard link satisfies all three and is recorded as `regular_file: true`.
- **预期行为**: The documented contract requires a new regular task file and explicitly excludes log/path aliases. A hard-link alias should not satisfy that configured deliverable check.
- **实际行为**: A hard-link alias is accepted as a passing artifact. The caller can therefore mistake a raw log or pre-existing file for the requested deliverable.
- **直接证据**: `require_new_output` is only called before launch. `Collection.collect` uses `target.is_file() and not target.is_symlink()` and has no `samefile` comparison against output/stderr/last-message paths or hard-link/inode identity check. The focused tests cover stale files, directories, symlinks, and literal output aliases (`tests/test_agent_run_results.py:291-300`) but not a runtime-created hard link. A synthetic postcondition probe hard-linked an event log to the artifact path and the adapter returned `validation_status=passed` with `regular_file: true`.
- **影响**: False-positive acceptance of an explicitly checked deliverable; the caller may accept the wrong content or an audit/log artifact.
- **建议改法和验证点**:
  - Reject post-run artifact aliases, at minimum `st_nlink != 1` and `os.path.samefile` against every retained log/final-message path.
  - Define and test the desired handling for hard links to arbitrary pre-existing files, or use a runner-owned fresh artifact directory/creation protocol that makes identity explicit.
  - Add a regression test that creates a hard link after dispatch and asserts `validation_status=rejected`.
- **修复风险（低/中/高）**: 中。It changes an opt-in postcondition and needs a deliberate definition for legitimate hard-link deliverables.
- **严重程度（低/中/高/严重）**: 中。

## Open Questions

The finding assumes the documented “not log/path alias” language is part of the configured artifact contract; if hard-link deliverables are intentionally allowed, the contract should say so explicitly and the test should reflect that choice.
