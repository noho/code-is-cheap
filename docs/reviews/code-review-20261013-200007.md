1. 「总控交付核对」为 Gate Order 语言中的新 gate 值：gateflow 与 phaseflow 双侧逐字一致（`总控交付核对`），状态不变量、entry criteria、Control Doc Updates 三处同步；standalone Gateflow 下读者即执行者，`Gate Group: draft PR` 给出具体核对步骤（:266–:272），无悬空角色。
2. `[fix -> 受影响面 re-review]` 条件步：绑定到 `## Gate Group: review / fix / re-review`，group 内显式覆盖 plan review 裁决与「不执行条件不成立的审核不属于 skip」，状态机可判定。
3. 「适用的独立审核数量 / 要求的双路并行」：与 baseline 同源措辞，要求来源为项目/用户显式规则（本仓库 `AGENTS.md` 双路并行），skill 未新造数量规则，也未移除双路要求。
4. 深审 OID 规则迁移：Gateflow 不再有 PR review gate 后，严格 OID 规则归属独立 PR Review Mode（保留原文），Gateflow 交付核对自带 OID 对定位 + 保存可取回版本 + 收尾复核的等价实质，无规则丢失、无循环引用。
5. 任务类型内容要求（feature/迁移重构/缺陷根因）：仅为 plan 内容 readiness 的一句式差异，不是 workflow 分支；gate 顺序、entry、pass 条件对所有类型一致。
6. Phaseflow `plan review` 出现处全部带「适用时/适用」或服从 Gateflow 条件；无强制 plan review、slice review、aggregate、重复 PR 双审、per-gate commit 残留。
