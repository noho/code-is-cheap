## Findings

### 1-未修复-[低]-Valid-gap regression does not pin ordinary failed-tool recovery
- **位置**: `plan.md` “Tests and exact expected assertions”, section 4 (`plan.md:174-180`), compared with existing recovery coverage at `tests/test_agent_run_results.py:115-152` and `tests/test_agent_run_results.py:778-788`.
- **问题类型**: 测试缺口
- **当前写法**: Section 4 requires a successful recorded tool read after turn start for selected-check coverage, while the explicit valid-gap matrix does not include a normal failed/expected tool command with the startup diagnostic.
- **反例/失败场景**: An implementation could accidentally treat a valid-gap `command_execution` with `exit_code=1` or `status=failed` as a recovery-fatal error. Existing adjacent-start tests would still pass, but the new gap path would reject an execution that should remain `completed`/`needs_review` with the recovered notice.
- **为什么有问题**: The goal requires preserving existing failure/optional-check behavior and explicitly says normal failed tool commands must not be mechanically rejected when expected or recovered. This interaction is new because the gap is newly accepted.
- **直接证据**: The current collector records nonzero/failed tool completions as anomalies at `scripts/agent-run-result.py:272-281`; existing tests already assert anomaly recovery for an earlier tool item at `tests/test_agent_run_results.py:120-122` and ordinary failed-tool adjudication at `tests/test_agent_run_results.py:778-788`, but neither combines that case with the new valid startup gap.
- **影响**: A regression could silently turn a valid recovered execution into `rejected`, losing the intended minimum correction and making the review claim incomplete.
- **建议改法和验证点**: Add one direct collector/fake-runner case with one valid startup gap, one expected failed tool completion after turn start, the exact recovered reconnect, and successful terminal/final. Assert `errors=[]`, `diagnostic_counts={errors:0, anomalies:2, warnings:1}`, `validation_status=needs_review`, `agent_status=completed`, and the recovered warning remains present. Keep the existing adjacent and no-retry controls.
- **修复风险（低）**: Low; one targeted regression case and no product behavior change should be sufficient.
- **严重程度（低）**: Low.

### 2-未修复-[中]-Recognition path policy is broader than the evidenced identity boundary
- **位置**: `plan.md` “Recognition contract” (`plan.md:65-87`) and “Non-goals and scope boundary” (`plan.md:20-26`), with residual ownership at `plan.md:226-228`.
- **问题类型**: 范围漂移 / 契约缺失
- **当前写法**: The plan fixes the message prefix and envelope but permits any lexical absolute POSIX path whose directory components are ASCII letters, digits, `.`, `_`, or `-` and whose basename is `config.toml`. The sanitized evidence contains only `/tmp/synthetic-codex/config.toml`; the plan gives additional synthetic examples but no confirmed source-of-truth list.
- **反例/失败场景**: A frame with the exact warning prose and a previously unobserved path such as `/future/config.toml` is treated as the evidenced startup diagnostic and can bridge the starts. Conversely, a valid native path outside this ASCII grammar is rejected. Either outcome makes the “supported path variation” contract ambiguous.
- **为什么有问题**: The goal requires exact evidenced recognition and says future envelope/text/path variants remain outside the exception without separate evidence and authorization. The plan’s broad grammar is a compatibility policy, not merely a test fixture parameter; it needs to be explicitly authorized or narrowed to the confirmed supported set.
- **直接证据**: The frozen fixture’s only path is `/tmp/synthetic-codex/config.toml`; `plan.md:83-87` defines the broader grammar and explicitly says paths need not exist. `goal.md` requires narrow coverage of the evidenced diagnostic and its supported path variation while prohibiting speculative compatibility.
- **影响**: The implementation could accept a false startup frame or reject the actual native frame, causing an unrecoverable review dispute after implementation. The plan itself lists “actual original path/envelope not covered” as a residual risk but does not make the support set a blocking contract decision.
- **建议改法和验证点**: Before implementation, have the controller compare the already-authorized native structure against the exact envelope/path policy and record the confirmed supported path set. Either narrow the regex to that set, or explicitly amend the goal confirmation to authorize the grammar. Add negative tests for grammar-valid but unauthorized paths and a positive test for every confirmed native path variation.
- **修复风险（中）**: Medium; the code change is small, but the contract decision must precede implementation to avoid rework or a misleading recovery proof.
- **严重程度（中）**: Medium.

No other material finding was established. The bounded counter/equality, exact key checks, malformed-row handling, lifecycle placement matrix, and unchanged terminal/final/exit/check/statistics plan are coherent and code-generation-ready subject to the two findings above.
