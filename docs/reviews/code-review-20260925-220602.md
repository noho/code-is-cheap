### 1-未修复-中-端口冲突预检范围 8788-8793 落后于路由真源 8788-8795
- **入口/函数**: `cmd_install` 端口预检
- **文件(行号)**: codex-agent/bin/codex-auto-review-shim-service:77,81
- **输入场景**: 目标 Mac 上有手工 shim 或残留进程监听 8794（mimo-fast）或 8795（glm-flash）时执行 `install`
- **实际分支**: `lsof -nP -iTCP:8788-8793 -sTCP:LISTEN` 不命中（:77）→ 预检通过 → 写 plist → bootstrap 成功
- **预期行为**: install 应在 launchd 启动前发现全部已配置路由端口的冲突（该检查的存在意义即预检 bind 失败）
- **实际行为**: launchd 启动 shim 后，`main()` 在 `_make_server` 对 8794/8795 bind 抛 OSError，打印 `cannot bind` 并 `return 1`（codex-agent/bin/codex-auto-review-shim:434-438）；plist `KeepAlive=true`（shim-service:57-58）使进程被反复拉起，进入 crash loop，且因 bind 在循环中逐个执行，8794 之前的端口虽已监听但进程整体退出，全部 8 条路由周期性不可用
- **直接证据**: 端口真源 codex-agent/shim-routes.json 含 8794、8795 两条路由；预检范围硬编码 `8788-8793`（shim-service:77,81）；bind 失败 `return 1`（shim:437）；`KeepAlive` true（shim-service:58）
- **影响**: install 报告成功但服务实际 crash-loop——静默坏状态，全部 profile 的自动审批反代不可用，需人工读 `~/.codex-agent/shim.log` 才能定位
- **建议改法和验证点**: 不再硬编码范围，install 时用已选定的 python 从 `$ROUTES` 解析端口集合再逐个 lsof（python 在 :70 已就位，解析 JSON 可靠）；或至少扩到 8795 并加注释指向 shim-routes.json。验证点：新增测试把检查范围钉在 shim-routes.json 的端口集合上（stub lsof 记录收到的 `-iTCP:` 参数与 routes 端口对比）；手工场景：8794 被占时 install 必须非零退出且打印占用者
- **修复风险（低/中/高）**: 低（动态解析）/ 中（若选择扩范围，需防再次漂移）
- **严重程度（低/中/高/严重）**: 中

### 2-未修复-低-Python 版本闸门使用 assert，PYTHONOPTIMIZE 环境下被静默剥离
- **入口/函数**: `resolve_python` 的探测 one-liner
- **文件(行号)**: codex-agent/bin/codex-auto-review-shim-service:32
- **输入场景**: 用户 shell 环境导出 `PYTHONOPTIMIZE=1` 或 `=2`（CI/性能调优配置会这样做），且候选解释器为 <3.11（如仅有 /usr/bin/python3 3.9.6 的机器——本机实测 /usr/bin/python3 即 3.9.6）
- **实际分支**: `"$candidate" -c 'import os, sys; assert sys.version_info >= (3, 11); ...'` 在 -O 下 assert 被剥离 → 任意版本 python3 退出码 0 → 打印其 executable 并被接受
- **预期行为**: 拒绝 <3.11 解释器，最终 die "找不到可用的 Python 3.11+"
- **实际行为**: 3.9 解释器路径被写入 plist；shim 在 launchd 下以未支持的版本运行（shim 是否使用 3.11-only 语法未逐行核验，但 README.md:69/:132 与 README.zh.md 均声明 3.11+ 要求，闸门意图明确）
- **直接证据**: shim-service:32 的 `assert`；已实证 `PYTHONOPTIMIZE=1 python3 -c 'assert False'` 退出码 0（assert 被剥离）
- **影响**: 错误解释器被固化进 plist，服务按错误版本运行或 crash-loop；install 无任何告警
- **建议改法和验证点**: 改为显式退出码：`sys.exit(0 if sys.version_info >= (3, 11) else 1)`。验证点：测试加 stub 旧版 python + 注入 PYTHONOPTIMIZE=1，断言 resolve 失败/die
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

### 3-未修复-低-bootout 提前后，端口冲突或写盘/bootstrap 失败把服务留在未安装中间态
- **入口/函数**: `cmd_install`
- **文件(行号)**: codex-agent/bin/codex-auto-review-shim-service:73-89
- **输入场景**: 重装时旧服务已加载，且另有手工 shim 占用 8788-8793 中某端口（或写盘失败、bootstrap 失败）
- **实际分支**: :73-75 bootout 成功 → :77 端口预检失败 → `return 1`（:82）；或 :86 写盘失败 / :89 bootstrap 失败 → die
- **预期行为**: 失败路径尽量不改变既有状态（旧实现顺序为：端口预检 → 写 plist → `bootout 2>/dev/null || true` → bootstrap，端口冲突时旧服务存活）
- **实际行为**: 旧服务已被卸载；磁盘 plist 仍是旧机器内容（或半截新文件）；下次 GUI 登录 launchd 自动加载该旧 plist，按旧 python 路径 crash-loop。可恢复（释放端口/修复后重跑 install 自愈），但 install 输出未提示"旧服务已被卸载"
- **直接证据**: 顺序 :73(bootout) < :77(端口预检) < :86(写盘) < :89(bootstrap)；diff 中旧顺序相反；~/Library/LaunchAgents 下 plist 由 launchd 在登录时自动加载（macOS 行为）
- **影响**: 失败路径的半提交状态；对用户表现为"install 失败 + 服务没了"，且失败摘要不含此事实
- **建议改法和验证点**: 任一失败分支补打印"注意：旧服务已卸载，修复后请重跑 install"；或调整为 写盘→bootout→bootstrap（把窗口缩到 bootstrap 一步），同时需解决旧服务自身占端口导致预检误杀的问题——可在 bootout 后短轮询等端口释放再预检。验证点：测试覆盖"lsof 命中时 install 非零退出且事件序列含 bootout 无 bootstrap"，并在输出中断言提示语
- **修复风险（低/中/高）**: 中（顺序回调会重新引入旧问题，需要配套端口释放等待）
- **严重程度（低/中/高/严重）**: 低
- **理论附加风险**: :74 bootout 与 :77 lsof 之间无等待；已确认 shim 无任何 SIGTERM handler（`rg signal|SIGTERM|atexit` 无命中），python 默认立即退出，竞态窗口极小，仅作记录。
