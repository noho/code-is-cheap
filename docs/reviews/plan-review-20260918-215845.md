## Findings

### 1-未修复-中-validation #1 的 "no CJK remains" 断言事实错误
- **位置**: plan `Tests/Validation` 第 1 条；对应 `README.md:3`
- **问题类型**: 测试缺口 / 不可直接实施
- **当前写法**: `grep -nP '[\x{4e00}-\x{9fff}]' README.md` → no output (no CJK remains)
- **反例/失败场景**: 正确实施 7 块翻译后，该 grep 仍输出第 3 行 `English | [中文](README.zh.md)`（语言切换链接，
  属刻意保留）。implementation agent 会面对两种跑偏：(a)  validation 永失败，无法判断自己是否完成；
  (b) 更糟——把第 3 行的 `中文` 也"修"掉，违反 non-goal（改动范围外内容、破坏中文版链接锚文本）。
- **为什么有问题**: 成功信号与代码事实冲突；断言没有为刻意保留的 CJK 留出例外。
- **直接证据**: `grep -nP '[\x{4e00}-\x{9fff}]' README.md` 输出包含 `3:English | [中文](README.zh.md)`；
  plan Non-goals 明确 "no other README.md content changes"。
- **影响**: review 不可验收 / 实施 Agent 跑偏改范围外内容。
- **建议改法和验证点**: 把断言改为"除第 3 行语言切换链接外无 CJK"，例如：
  `grep -nP '[\x{4e00}-\x{9fff}]' README.md` 的输出必须恰好是 `3:English | [中文](README.zh.md)` 一行；
  或 `grep -nP '[\x{4e00}-\x{9fff}]' README.md | grep -v '^3:'` 无输出。同步修正 plan 的 success signal 描述。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
