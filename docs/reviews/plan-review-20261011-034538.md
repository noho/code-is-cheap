## Scope and conclusion

The plan is materially aligned with the binding goal: it proposes one behavioral slice, keeps unknown and unrecovered errors fatal, requires same-execution completion and all selected checks before changing a recognized notice to a warning, preserves native/process failure semantics, and excludes model/route proof fields and broad error downgrading. The private feasibility evidence is credible for the observed shape and the proposed classifier, but it is prototype evidence and does not prove the integrated production implementation.

No blocking implementation defect is established by the frozen plan. The plan is `pass-with-risks` pending adjudication of the findings below and explicit resolution of the open protocol assumption. The findings are actionable before or during S1; they do not justify a broad redesign.

## Binding behavior tested

- Goal G1: only a narrowly recognized Codex connection notice with reliable later success in the same valid recorded execution may be recovered; unknown or ambiguous errors remain fatal.
- Goal G2: recovered notices remain diagnostics with original event location; ordinary anomalies may still produce `needs_review`.
- Goal G3: unrecovered/unknown errors, `turn.failed`, native or postprocessing nonzero, malformed/conflicting/missing terminal or final, and selected-check failures remain rejected.
- Goal G4: validate the real log offline and a small independent synthetic matrix through collector/runner boundaries.

## Required review lenses

- **Goal-bound minimal design**: D1-D4 and S1 map to G1-G5. The plan avoids retry scheduling, route/model proof, schema changes and generic error taxonomy. The stricter D2/D3 frame contract is the main scope tension because it is stronger than the single observed structural sample.
- **Architecture boundary**: classification remains in `Collection`, while the shell runner remains the exit-code owner. This is a clean boundary and avoids a shell downgrade path. Private proof state is internal and no public report schema change is proposed.
- **Best practice**: the design is testable through the existing fake-runtime harness, preserves raw logs and diagnostic locations, fails closed on unknown evidence, and keeps selected checks authoritative. The exact diagnostic reason priority is marked “suggested”, which is acceptable only if S1 tests assert stable user-visible outcomes rather than an undocumented reason string.
- **Optimal-solution**: a literal matcher plus deferred diagnostics is simpler than a generic retry/error framework and is appropriate for one behavioral slice. The alternative of recognizing only the single observed `1/5` literal would reduce false positives but would reject the plan's explicitly synthetic attempt family; the plan should make that contract choice visible.
- **Overengineering**: exact start-frame shapes, exact key sets and ordinal 1/2 placement are additional proof fences. They are defensible as conservative same-execution evidence, but the plan must not present them as proven protocol invariants from one log.
- **Overcoupling**: S1 combines matcher, proof state, finalization, tests and short docs. The coupling is justified as one user-visible behavior, but documentation should stay limited to the classification contract and not become a protocol reference.
- **Agent-facing clarity**: file ownership, allowed files, stop conditions, completion signal and negative cases are clear. The implementation agent still needs deterministic guidance for “selected last completed agent-message frame” and for the exact reason text/order if diagnostics are compared in tests.

## Findings

### 01-accepted-candidate-[中]-strict start-frame proof fence is under-evidenced and can create false negatives
- **位置**: `plan.md` D2/D3, especially lines 87-123; `goal.md` G1/G3; residual table lines 263-264.
- **问题类型**: 过度设计 / 目标漂移 / false-negative risk
- **当前写法**: Recovery requires exactly one valid `thread.started` and one valid `turn.started`, exact key sets, and parsed-event ordinals 1 and 2. It also requires the selected final and terminal frames to have exact observed key sets.
- **反例/失败场景**: A Codex stream with the exact recognized notice, a later valid final and `turn.completed`, but a legitimate protocol/control frame before the starts or an extra nonsemantic field on a start/final/terminal frame, is rejected even though the notice and success are in one recorded execution and no hard failure exists.
- **为什么有问题**: The binding goal requires proof of same valid execution and rejects malformed/ambiguous terminal/final, but it does not establish that the observed exact shapes and ordinal placement are protocol invariants. The plan's own residual language says unobserved envelopes are future protocol work, while D2/D3 makes them a current recovery gate.
- **直接证据**: `goal-log-check.json` and `structure-results.json` show only one observed sequence: starts at lines 1-2 and exact observed frame keys. The plan explicitly labels missing/duplicate starts and extra native frame fields as residual areas. No second protocol sample establishes the invariant.
- **影响**: Valid recovered executions can be rejected (false negatives), causing needless reruns or a misleading claim that the classification is fixed only for one fixture. Conversely, without an explicit contract the implementation agent may accidentally loosen the fence and create false positives.
- **建议改法和验证点**: Decide and document one of two contracts before S1: (a) keep the strict fence as an intentional fail-closed supported-shape contract, add a named negative test for every extra field/preamble variant and record the limitation; or (b) narrow the proof to the minimum same-execution evidence needed (unique starts, notice-to-final-to-terminal ordering and existing hard checks) while leaving generic frame-shape validation out of this slice. Add an explicit test for the chosen boundary and make the reason deterministic if diagnostics are asserted.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### 02-accepted-candidate-[中]-ordering test matrix omits a notice after the selected final but before the terminal
- **位置**: `plan.md` D3 ordering formula line 116 and required test row `test_codex_connection_notice_requires_same_execution_completion` line 177.
- **问题类型**: 测试缺口 / false-positive risk
- **当前写法**: The test row names final-before-notice, notice-after-terminal and other terminal failures, but does not explicitly specify a mixed stream with `notice < selected_final < notice < completed_terminal`.
- **反例/失败场景**: `thread.started`, `turn.started`, recognized notice A, valid final, recognized notice B, `turn.completed`. The plan's formula must reject because `last_notice` is after `selected_final`; an implementation that checks only the first notice or only notice-before-terminal can incorrectly recover the stream.
- **为什么有问题**: The plan makes first/last notice ordering a safety predicate, but the listed assertions do not force the implementation to use the last candidate and the selected final's exact physical order. This is a direct route to a false-positive recovery under G1/G3.
- **直接证据**: D3 explicitly states `first_notice <= last_notice < selected_final < completed_terminal`; the experiment cases include `final-before-notice-only` and `notice-after-terminal`, but not the mixed final-then-notice-before-terminal case. The planned test row does not name that case.
- **影响**: A subtle ordering bug could downgrade an unrecovered/ambiguous stream to warning and exit 0, violating the binding rejection rule.
- **建议改法和验证点**: Add one focused subcase with at least two notices and a valid final between them, assert `validation_status=rejected`, runner/collector exit 1, and the late notice's original line is retained as an error diagnostic. Also assert the proof uses `last_notice`, not merely `first_notice`.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### 03-accepted-candidate-[低]-G5 report-contract assertions do not explicitly lock result status and absence of proof fields
- **位置**: `plan.md` G5 and expected behavior line 26; required test row line 175; current report construction `scripts/agent-run-result.py:398-410`.
- **问题类型**: 测试缺口 / 目标对齐
- **当前写法**: The recovered test row promises native final/usage/log preservation and status behavior, but does not explicitly assert `result_status` remains `not_assessed`, schema remains unchanged, or that no model/route/proof fields were added.
- **反例/失败场景**: An implementation adds a route/model proof field or changes `result_status` while keeping final, usage, logs and exit behavior correct; the new focused tests still pass even though G5 forbids those changes.
- **为什么有问题**: G5 is a binding non-goal and the plan explicitly says no proof fields/schema bump. The current baseline report includes `schema_version=1` and `result_status="not_assessed"`, so those are concrete compatibility facts that can be locked cheaply.
- **直接证据**: `goal.md:30` says no route-proof fields or broad schema redesign; `plan.md:26` says `result_status` remains `not_assessed`; `scripts/agent-run-result.py:399-410` exposes the existing schema/status fields. The proposed test descriptions do not name these assertions.
- **影响**: Goal drift could enter through a technically passing implementation and become difficult to detect in later review.
- **建议改法和验证点**: In the recovered clean and anomaly subtests, assert `schema_version == 1`, `result_status == "not_assessed"`, and the report key set is unchanged (or explicitly assert absence of model/route/proof keys). Keep this as a focused contract assertion, not a generic schema redesign.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
