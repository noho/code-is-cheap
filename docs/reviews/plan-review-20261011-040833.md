## 4. Findings（新发现）

### 新-1-未修复-中-支持的形状边界声明大于可测谓词：ordinal≥3 的未知事件类型不影响任何 fence，含未观察帧的流仍可恢复
- **位置**: plan.md D2（L97-106，尤其 L106 "This deliberately refuses recovery for unobserved envelopes …"）、D3 谓词 1-5（L110-124）、负例表（L190-205）、`test_codex_connection_notice_requires_same_execution_completion`（L182）。
- **问题类型**: 契约缺失（声明边界未被谓词/负例闭合）
- **当前写法**: D2 声称保守边界拒绝 recovery for "unobserved envelopes … preamble frames or items between starts"；但 D3 的谓词只约束：(i) 五个已知帧种类的精确 key 形状、(ii) 唯一 start 位于 parsed-event ordinal 1/2、(iii) 终端唯一 `turn.completed`、终稿有效且满足 `thread<turn<first_notice≤last_notice<final<terminal`、(iv) exits 0/0、(v) 终局化前 `counts["errors"]==0`。
- **反例/失败场景**: `thread.started`(ord1) / `turn.started`(ord2) / `{"type":"session.configured"}`(ord3) / recognized notice / valid final / `turn.completed`，native/precollection 0/0 → 五个谓词全部通过：未知 kind 在 `codex()`（agent-run-result.py:194-239）中不匹配任何分支（仅 `*.failed` 后缀进 anomalies，L238-239），不产生 `note()`，不影响 start 计数与序数，不影响顺序链 → **该流将恢复为 warning/exit 0**。未知帧出现在 notice 与 final 之间同理放行。
- **为什么有问题**: adjudication（L18）既定前提是 "only known notice and reliable success evidence supported; unobserved protocol frames cannot be assumed harmless"，goal（L45）要求 "current rule must fail closed on unknown evidence"；计划自称拒绝未观察 envelope，但机制未交付该子情形。实现 Agent 将面对两种合理读法：(a) 按谓词实现 → 交付边界窄于声明（含未观察帧的流仍恢复）；(b) 按声明句实现 → 新增 kind 白名单等未经评审的谓词与更多假阴性（scope creep）。两种读法都不会被 S1 具名测试捕获——现有负例全部是五类已知帧的字段变体或 start 序位错位（L194-205），测试清单 L182 的 "prefix/orphan event or an item between starts" 也只覆盖 start 之前的序位移动。
- **直接证据**: D3 谓词枚举（plan L110-124）无 "全部事件 kind ∈ 已知集" 类约束；D2 帧表（L99-104）只定义已知帧的形状；负例表 8 项（L194-205）无未知 kind 情形；基线 `codex()` 分派对未知 kind 静默忽略（scripts/agent-run-result.py:194-239）；我的独立实验确认未知 kind 不触碰可测 fence（§3.9 的基线分派行为 + 谓词逐条核对）。
- **影响**: D2 的保守边界声明与 S1 测试集不自洽，review 无法从"谓词+测试"推出实际边界；若按字面实现，含未观察协议帧的流会获得 recovered 分类，与 controller 明确前提相反。
- **建议改法和验证点**（二选一，均不扩大协议支持面，均保持 ordinary no-candidate 流基线行为/G5）: (a) 最小修改——把 L106 改为 "unobserved *shapes of the named proof-bearing frames*"，并在 residual 表（L334-336 附近）补一行 "post-start unknown event kinds are ignored exactly as in baseline and do not act as a recovery fence"；(b) 收紧——增加一条显式谓词（候选存在时，任何 parsed event 的 type 不在已知集合 `{thread.started, turn.started, turn.completed, turn.failed, error, item.started, item.completed, item.updated, rate_limit_event, *.failed}` 即拒绝），配具名负例 `unknown-frame-kind-after-starts`（恢复拒绝、候选进 errors、rejected/1、原文行号保留）与成对 no-candidate 对照（基线 passed/0）。验证点：S1 必须锁定所裁定行为，无论选 (a) 还是 (b)。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
