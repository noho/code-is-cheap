## Focused Verification

### Two-Hop Synthetic Wiring

The fix closes the previous accidental-traffic hole. The Codex-to-shim hop is not mistaken for the shim-to-upstream hop:

- Managed provider tables retain provider IDs and request prefixes but point to each fixture shim port.
- Each selected Codex connection is fully overridden in the fixture-owned endpoint file with loopback upstream URL, synthetic wire model, and synthetic key.
- The fixture-only opener asserts exact host/port/path before unchanged forwarding.
- Preflight resolver/route snapshots and retained listener identities reject missing overrides or any nonfixture destination.
- Kimi and guardian forwarding use the same two-hop isolation and endpoint-owned wire snapshot.

### Narrow Recovery Semantics

The revised plan now promises exactly the controller's narrowed recovery boundary. It covers ordinary conversion-block copy, replacement, registry update, and installed-pair verification failures. It explicitly excludes atomic cross-file reader visibility, concurrent-writer coordination, SIGKILL/power loss/disk destruction, failed restoration I/O, and ancillary shim/service/business deployment. Those exclusions are residual risks, not hidden claims of transactionality.

### Native Parser And Route Behavior

Native parser authority remains unchanged. Python checks are limited to source integrity, explicit mapping/card/path/budget invariants, selected tool-mode semantics, and authorized GLM/Kimi deltas. The plan does not add a generic schema/configuration framework or duplicate native nested validation.

The prior stable controls remain sufficient for all-source parse, serialized `max`, MiMo Lite moving tools into `additional_tools`, and host default true. The revised plan does not repeat those source-wide experiments. It preserves the existing route-wide MiMo `json_schema` to `json_object` behavior and requires focused ordinary/guardian coverage plus both README disclosures.
