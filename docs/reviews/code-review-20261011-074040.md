## Findings

### F1-未修复-低-其他标签 PEM 段与内嵌分隔符行被误判为 malformed delimiter

- **入口/函数**: `prepare_codex_ca`（`scripts/agent-sandbox`），由 `main()` 的 Codex `--check`（line 661）与 launch（line 681）调用。
- **文件(行号)**: `scripts/agent-sandbox:447-462`（pseudo-delimiter `candidate` regex 在 447；`delimiter.fullmatch` 判定与 `malformed … delimiter` 抛出在 459-462）。
- **输入场景**: 选中的 CA 文件除有效证书外还包含：(a) 标签仅以受支持标签开头的 PEM 段，例如 `-----BEGIN CERTIFICATE REQUEST-----` … `-----END CERTIFICATE REQUEST-----`（CSR）；或 (b) 在前后文本中内嵌完整分隔符拼写的行，例如 `# -----BEGIN CERTIFICATE-----`。
- **实际分支**: `candidate.search(line)` 以字边界命中 `BEGIN|END` + `CERTIFICATE`；`delimiter.fullmatch(line)` 为 None → 抛 `invalid Codex CA bundle … reason=malformed CERTIFICATE delimiter`；扫描在该文件中的有效证书被验证之前中止，`env` 不被改写、不启动 runner。
- **预期行为**: `plan.md:122` 仅要求拒绝“naming either supported certificate label”的 delimiter-looking 行且拼写不完整者，并明确 “Noncertificate surrounding text remains ignored”；其他标签的 PEM 段（如 CSR）属于非证书文本，应与被忽略的 `X509 CRL` 段同样被忽略。
- **实际行为**: 只要出现 (a)/(b) 行，setup 立即以 `agent-sandbox: invalid Codex CA bundle: … reason=malformed CERTIFICATE delimiter` 退出 1 —— 即使同一 bundle 含有效证书；调用方必须清理 bundle 才能启动。
- **直接证据**: 本 reviewer 直接 probe（合成字节，`$TMPDIR` 隔离目录）: `csr_only` REJECT；`csr_beside_valid`（有效证书 + CSR 段）REJECT；`comment_with_delimiter` REJECT；而 `prose_no_dashes`（无横线的 BEGIN CERTIFICATE 字样评论）ACCEPT、`key_beside_valid`（PRIVATE KEY 段在旁）ACCEPT、`crlf`/`trusted_crlf`（CRLF bundle）ACCEPT。`tests/test_agent_sandbox.py` 无任何其他标签 PEM 段的用例（grep 无 `CERTIFICATE REQUEST`/`REVOCATION`），该行为是无测试固化的 candidate regex 宽度副作用。
- **影响**: 对携带非证书 PEM 段或装饰性注释的调用方自定义 bundle 造成 fail-closed 的 setup 失败——阻挡的正是本工作单元要恢复的 isolated Codex HTTPS 启动，直到 bundle 被清理。无边界绕过、无静默接受、无错误信任输入（失败发生在 env 改写与启动之前）。
- **建议改法和验证点**: 当 candidate 命中的受支持标签词后面紧跟更多标签字符（即该行实际命名的是另一个 PEM 标签，如 `CERTIFICATE REQUEST`）时，按非证书文本忽略该行，而非报 malformed；对内嵌分隔符注释行 (b) 做出显式决定（接受为被忽略文本，或保留严格失败并写入文档）。“受支持标签的拼写残缺/截断”仍应拒绝。回归点：CSR 段置于有效 ordinary/trusted 证书前后（含/不含 CRL）应通过；装饰性注释行按决定固化用例；全部现有 malformed/nested/orphan/mismatched/companion-hiding 用例保持通过。
- **修复风险（中）**: 触碰 fail-closed 分隔符分类逻辑，必须不重新打开“有效证书不得掩盖畸形伴随段”的保证；在根授权之前无法测量 native Codex 对此类 bundle 的真实接受度。
- **严重程度（低）**: 仅影响自定义 bundle 的可用性；失败有定位、无安全/状态后果；默认系统 bundle 与整洁 bundle 路径不受影响（离线套件与既有 kernel/live 证据均通过）。
