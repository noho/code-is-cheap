## Findings

### 1-未修复-[高]-Recovered notice diagnostics can be entirely displaced by preexisting same-category diagnostics

- **位置**: Plan D2 candidate retention (`plan.md:92`), D4 emission/count rules (`plan.md:127-133`), and `test_codex_connection_notice_diagnostic_bounds` (`plan.md:180`); baseline `Collection.note()` at `scripts/agent-run-result.py:147-153`.
- **问题类型**: 契约缺失 / 测试缺口 / 可观测性边界错误
- **当前写法**: D2 retains at most 20 candidate pairs. D4 emits those pairs through `note()` only after existing session diagnostics, then adds `candidate_count - len(retained_pairs)` to the selected category count. The plan treats retained pairs as effectively displayable.
- **反例/失败场景**: A fully recovered Codex stream already has 20 same-category warnings before finalization, then contains 25 recognized notices and valid later completion. `self.warnings` is already full. Every finalizing `note("warnings", ...)` increments the count but appends nothing because `note()` only appends while `len(target) < DIAGNOSTIC_LIMIT`. The result can contain 45 warnings and `diagnostics_truncated=true`, yet zero recovered-notice message/line entries.
- **为什么有问题**: G2 requires the original recovered notice and event location to remain diagnostics. Complete counts plus raw logs do not satisfy that report contract. The proposed “undisplayed” arithmetic is also wrong when retained candidates are dropped by the existing category-level cap.
- **直接证据**: `scripts/agent-run-result.py:147-153` increments the category unconditionally but appends only below 20. D4 runs after existing diagnostics (`plan.md:127`) and specifies retained-pair emission at `plan.md:132`. The bounds test covers 25 notices without 20 preexisting warnings, so it cannot expose displacement.
- **影响**: A valid recovered execution may pass or need review while omitting the very diagnostic evidence needed for adjudication; reviewers cannot distinguish a recovered notice from an undocumented silent count increase.
- **建议改法和验证点**: Define deterministic display priority that guarantees bounded recovered-candidate samples are present after proof finalization, while preserving complete counts and the 20-entry/2000-character limits. Recompute truncation from actual displayed diagnostics. Add a case with 20 preexisting warnings plus 25 recognized notices and assert that representative recovered message/line entries remain visible, total warning count is 45, and truncation is true. Apply equivalent bounded retention clarity to failed candidates.
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### 2-未修复-[中]-Exact frame-key fences are broader than the proven recovery requirement

- **位置**: D2 known-frame table (`plan.md:96-105`) and D3 predicates 1-3 (`plan.md:111-121`).
- **问题类型**: 目标漂移 / 过度设计 / 非最优方案 / false-negative risk
- **当前写法**: Notice-bearing streams require exact key sets for `thread.started`, `turn.started`, `turn.completed`, and the selected final event/item. Any additive field fails recovery even when it does not contradict identity, success, ordering, or final content.
- **反例/失败场景**: A stream with one valid start pair, the exact recognized notice, a final `item.completed/agent_message` whose item also has `status:"completed"`, and `turn.completed` with `type`, `usage`, and harmless `duration_ms` is semantically recovered and accepted by the baseline extractor. The proposed proof rejects it solely because the envelopes were not observed verbatim.
- **为什么有问题**: The binding goal rejects malformed or ambiguous terminal/final evidence, but the plan has not established that every additive field makes those frames malformed or ambiguous. Evidence proves the observed shapes, not their exclusivity. Treating all unobserved metadata as invalid adds a hidden acceptance criterion and creates avoidable false negatives.
- **直接证据**: `structure-results.json` proves only the recorded key sets. Baseline `Collection.codex()` accepts the selected text and terminal extraction without exact-key rejection (`scripts/agent-run-result.py:194-239`). The prototype tests a contradictory `status:"failed"` final but no benign additive-field counterexample (`experiment.py:198-205`).
- **影响**: Legitimate provider metadata could keep a demonstrably recovered execution rejected, while the plan classifies that behavior as outside-goal protocol work. Conversely, simply removing all fences would permit concatenated/ambiguous evidence, so the plan needs a narrower semantic boundary rather than an all-or-nothing exact schema.
- **建议改法和验证点**: For each fence, state the specific ambiguity it excludes and keep only predicates needed for same-execution proof: unique ordered starts, unique successful terminal, nonblank selected final after all notices, and no contradictory `error`/failed status/terminal fields. Either allow harmless additive metadata or provide protocol evidence plus explicit goal confirmation that exact envelopes are required. Split tests into benign additive fields that must recover and contradictory fields that must reject.
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中

### 3-未修复-[中]-Planned tests do not lock the unchanged report contract or absence of proof fields

- **位置**: Required tests (`plan.md:175-182`), D4 invariants (`plan.md:134`, `plan.md:146`), and prototype preservation assertions (`experiment.py:118-120`).
- **问题类型**: 测试缺口 / goal alignment
- **当前写法**: New tests specify statuses, exits, diagnostics, final/usage/logs, selected checks, and process failures. The prototype preserves selected report values but does not compare the full stable key set.
- **反例/失败场景**: An implementation adds `recovery_proof`, `model`, or `route` fields, changes `result_status` from `not_assessed`, or bumps `schema_version` on recovered streams while preserving all listed assertions. The focused tests can still pass.
- **为什么有问题**: G5 explicitly forbids proof fields and requires preserved report behavior. The default clean-run test checks `result_status`, but the recovered and rejected variants do not, so the new branch is not contract-tested.
- **直接证据**: `experiment.py:118-120` omits `schema_version`, `source`, `result_status`, `tool_evidence_scope`, and the report key set from preservation assertions. The S1 test table does not require those assertions on recovered, failed, or Claude paths.
- **影响**: Goal drift can ship without failing the prescribed suite, and downstream consumers may observe new proof/model/route semantics despite the non-goal.
- **建议改法和验证点**: Assert `result_status == "not_assessed"`, `schema_version == 1`, `source == "subagent_report"`, `tool_evidence_scope == "recorded_events_only"`, and the unchanged report key set on at least one clean recovery, one proof failure, and one Claude control. Explicitly assert no recovery-proof/model/route keys are added.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
