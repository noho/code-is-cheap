## 6. Required review lenses（逐 lens 结论）

### 6.1 精确匹配（D1）
- 逐字 `re.fullmatch`、无 strip/casefold/substring；事件 key 集恰好 `{type,message}`；`type=="error"`；`message` 为 str。核验：真实 message 逐字与 regex 互匹；`[1-5]` 仅 ASCII 数字（Unicode `１` 经实验拒绝）；`0/5`、`6/5`、`1/6`、前缀/后缀/换行变体全部走既有立即 error 路径（实验负例）。识别面没有溢出到未知错误族：D1 末段明确 embedded item error、stderr、Claude error 不走该 helper。
- `2/5..5/5` 是"同一边界语法内的合成扩展"（观察仅 1/5）。判断：可接受——接受面扩大不产生假阳性路径（见 6.5），且 plan 已显式声明其非观察来源。
- 结论：识别谓词精确、最小、fail-closed；无 finding。

### 6.2 Proof 与顺序语义（D2/D3）
- "同一执行"证据链：唯一 start 对（序数 1/2）→ 起始形状 → `thread<turn<first_notice<=last_notice<final<terminal` → 唯一 `turn.completed` 且帧形状已知 → 选中的 final 帧有效 → `exit_code==0 && runner_exit_code==0` → 终局化前 `counts.errors==0`。每条谓词都能追溯到 G1 的 "subsequent success in the same valid recorded execution" 或 G3 的明文拒绝项。
- 冗余保护已核验：重复/冲突终端、post-terminal 事件、`turn.failed`、parse error 在既有路径中已产生 error 计数，本身就否决 proof；新 fence 是第二道锁（实验 `duplicate-terminal`、`failed-then-completed`、`notice-after-terminal` 均 rejected）。
- 顺序关键点：notice 之后的 final 才被接受；notice 在 final 之后（`final-before-notice-only`）与 notice 在 terminal 之后（`notice-after-terminal`）均不可恢复——与"歧义保持拒绝"一致，属故意假阴性（R3）。
- 结论：谓词闭合、顺序链完整，无 finding。

### 6.3 额外 frame fence 的必要性与最小化（逐条）
| Fence | 必要性判断 | 代价/豁免 |
| --- | --- | --- |
| `thread.started` 恰好 `{type,thread_id}` + 非空 str id | 必要：这是"有效录制执行"与同执行会话身份的最低证据；防止拼接/未知前缀流被当作恢复证据 | 未观察 envelope 变体 → 假阴性（R1，已分类） |
| `turn.started` 恰好 `{type}` | 必要：pin 单 turn 结构与序数 | 同上 |
| `turn.completed` keys ⊆ `{type,usage}`、唯一终端 | **冗余保险中最弱的一条**：唯一性/冲突/失败已由既有 `self.terminal` 权威处理（错误计数本身否决 proof）；形状子集检查只是 fail-closed 加固 | 若未来成功帧带良性附加字段会假阴性；如出现真实证据，可只放宽这一条（R1/Q2），当前无需改 |
| selected final 帧 `{type,item}` / `{id,type,text}` + 非空 | 必要：确保 final 本身是所观察协议的有效 final，否则恢复证据不成立；仅作用于 notice-bearing 流 | 同上 |
| 序数 1/2 + 全程唯一 start 对 | 必要：same-execution 结构证据；有 orphan-prefix / item-between-starts / two-turns / two-threads 负例 | 同上 |
| 顺序链（含 `first_notice`、`last_notice`） | 必要：G1 "subsequent" 语义 | 仅拒绝歧义 |
| exits 0/0 | 必要：G3 明文 | 无 |
| `counts.errors==0`（终局化前） | 必要：G3 "later success cannot erase prior failure" | 无 |

结论：无多余抽象/层/schema——1 个纯 matcher、有界状态、2 个私有方法、1 个调用点；fence 越界仅体现在"对未观察成功帧的严格性"，方向是拒绝而非放行，符合 Goal 授权的 fail-closed。**不构成 overengineering，也不构成 goal drift。**

### 6.4 诊断上限与计数算术（D4）
- 核验算术：`note()` 对每个保留 pair +1；再补 `candidate_count - len(retained_pairs)` → 总增幅恰为 candidate_count，无双重计数（实验 `bounded-25-notices`：warnings=25、list=20、`diagnostics_truncated`=true，逐项对上）。
- 既有 per-category 20 条上限、2000 字符截断、`diagnostics_truncated` 公式（含 `any(v>20)`）全部复用，未改。
- `proof 计算先于发射`、`不重置/不扣减 counts`、`不使用前 20 条样本作证明源`（首尾行号与计数覆盖全部候选）均与实验实现一致；测试 6 直接锁定"无 proof 时 25 条全部计为 errors、有 proof 时 25 警告"。
- 一个被接受的细节：失败流中候选诊断在 `errors` 列表尾部追加（解析位次变化，行号保留）——见 R4，无程序性消费者依赖顺序。
- 结论：bounds 与计数正确、可测；无 finding。
