## Assumptions tested

1. **Acceptance coupling exists.** Confirmed offline: native 0 + valid final + missing `--artifact` returns outer 1 with `validation_status=rejected` (`scripts/agent-run-result.py:474–477,522–528,576`; probe B).
2. **Aux copy overrides native 0.** Confirmed: native 0 + valid final + raced `--last-message` destination returns outer 1, `runner_exit_code=1`, rejected; destination is not clobbered and the temp final is retained (`scripts/codex-agent-run:510–527,542–546`; probe C).
3. **Setup failure fabricates a native exit.** Confirmed: a launcher returning 2 before starting any CLI yields outer 2 plus a report with `runtime_exit_code=2` and no native frames, indistinguishable by code from a real CLI exiting 2 (`scripts/agent-tools.zsh:81–120,313–448`; `scripts/agent-endpoint.py:173–231,250–278`; probe A). The narrow pre-exec handoff is necessary.
4. **Codex can mask the native exit.** Confirmed: with `setopt pipe_fail` and a 200 KB prompt, a launcher returning 0 without reading stdin yields outer/`runtime_exit_code` 141 (producer SIGPIPE) (`scripts/codex-agent-run:498–505`; probe D). The plan’s pipeline/terminal-exec fix is required.
5. **Handoff minimality.** Error-only, invocation-local, no success handshake or stored lifecycle state; the old general launch/outcome channel is explicitly dropped (`plan-v2.md:43`). The CLOEXEC-FD + terminal-exec mechanism is feasible on this host (offline `sysopen -o cloexec,creat` check); custom-launcher behavior remains open question 1.
6. **Aux/no-clobber semantics.** Prelaunch destination checks and post-run race checks remain; aux failures are diagnostics only; the retained temp path is the `logs.last_message` fallback (`plan-v2.md:27,45,67`).
7. **Parser attribution.** Codex final = latest completed `agent_message`; Claude final = unique root result; nested/intermediate text is not a substitute; unrelated malformed frames or native negative metadata do not erase an attributable final (`plan-v2.md:33–35`). The current root-assistant fallback is a migration decision (open question 3).
8. **Migration/long-final coverage.** Schema v2 removes the old fields and matrix row 5 requires full-final equality (whitespace/Unicode) through collector and both runners (`plan-v2.md:18–31,58,67`). Direct consumers listed cover the READMEs, skill/reference, `test_agent_run_results.py`, `test_official_catalog_runtime.py:401–419,455–467` and `test_agent_sandbox_runtimes.py:120–127`; the two native opt-in suites stay unexecuted under the mandatory environment, as stated (`plan-v2.md:69–85`).

## Findings

### 1-未修复-中-警告文本不判定要求未明确进入 plan-v2 契约与回归

- **问题类型**: 契约缺失 / 测试缺口 / 新 binding 要求未纳入。
- **当前写法**: The plan removes three diagnostic classes, “tool-text semantic suspicion heuristics” and severity rollups, and keeps stderr notices as concise source-linked observations. It never states that warning/diagnostic free text is opaque, that no text recognizer, keyword/known-message whitelist or benign/recovery classifier may remain, that known and unknown wording receive identical handling, or that original warning text is preserved rather than summarized. The matrix has no wording-variation regression.
- **反例/失败场景**: An implementer collapses the classes but keeps or re-creates the current `[claude-code:unrecognized_model]` prefix check, or adds a known-SSE allowlist while “summarizing” diagnostics. A known warning is filtered/classified differently from an unfamiliar catalog/SSE warning; exit/final may be unchanged, but the wrapper still judges warning text, contrary to the binding requirement. No regression varies only wording, so this survives review.
- **为什么有问题**: `scope-amendment.md:16` requires no warning-text judgment, identical treatment, preserved original text, and offline regressions varying only SSE/catalog/unknown wording. C-P4 accepted this as unfixed. plan-v2 predates the amendment and “tool-text” is narrower than “warning/diagnostic free text”; the controller’s “reinforces” reading is compatible but not yet an explicit contract or validation target.
- **直接证据**: `scope-amendment.md:16`; `decisions.md:46–51`; current code `scripts/agent-run-result.py:505–513` (`benign = ... startswith("[claude-code:unrecognized_model]")`, then `note("warnings" if benign else "anomalies", ...)`); plan lines 35, 37, 57.
- **影响**: A binding user requirement can be missed in implementation; an opaque-warning text classifier remains; review acceptance is ambiguous; no evidence proves wording-independent behavior or exact text retention.
- **建议改法和验证点**: State explicitly that stderr/diagnostic free text is opaque and preserved verbatim with source; remove the prefix check and any wording-based classification/filtering; `message` must not be a semantic rewrite. Add offline fixtures holding the structured envelope/exit/final constant while varying only SSE, catalog and unfamiliar warning wording, asserting identical outer/native exit, identical final, and exact retained text. If C-P4 stays solely at implementation/code-review destination, record that explicitly rather than relying on the plan’s generic wording.

## Open questions

1. **Custom `AGENT_TOOLS_FILE` launchers (M-01).** The plan says “failure to establish the handoff is setup failure” and “unobservable launch/wait outcome is reported as unknown” (`plan-v2.md:43`), but does not define a user-supplied launcher that ignores the channel. If it exits nonzero without writing, the runner could forward that code as a fabricated native exit; if an empty channel means setup failure, existing custom/launcher-fake paths break. Define the seam and add one custom-launcher case to the native-entry tests. Owner implementer/controller; destination setup-boundary implementation, docs, code review.
2. **Opt-in host-disabled assertion (M-02).** `tests/test_official_catalog_runtime.py:455–462` asserts `returncode != 0` and `validation_status != "passed"`. Under the thin contract this must compare the wrapper exit with the observed native exit and retained evidence instead of assuming the host-disabled task implies nonzero. The plan lists the file but not this rule. Owner implementer; destination schema-v2 test migration/code review.
3. **Claude partial/duplicate root results.** plan-v2 says “unique root result string” and “no replacement final prose,” while current code keeps a prior root assistant text as `final_answer` when the result is blank/missing (`scripts/agent-run-result.py:400–403`) and tests assert `partial root` and first-result preservation (`tests/test_agent_run_results.py:289–319,440–464`). Confirm migration should return null/absent final (partial text only in logs) and treat duplicate/conflicting root results as ambiguous rather than silently preserving the first. Owner implementer/controller; destination parser migration and code review.
4. **Diagnostic location detail.** The new `{message, path, line}` entry drops `stream` and `proof_line`; for canary mismatches the JSONL event line and proof line can differ. If one `line` cannot carry both, keep the proof line in `message` or document the chosen rule. Owner implementer; destination collector/code review.
